# Reference Case Evidence V0

## Summary

This method is the archival reference-case path for the benchmark.

It is not a fresh probing method. Instead, it takes an existing historical investigation that has already been normalized into benchmark-core evidence artifacts and wraps it in the same submission contract used by ordinary benchmark runs.

## Why this method exists

The benchmark needs to support two realities at once:

- local seeded tasks that can be rerun through baseline methods,
- and historically important reference cases that should not depend on new third-party API traffic.

`reference_case_evidence_v0` exists so those historical cases can still participate in the benchmark ecosystem without pretending they were generated by the scripted or hybrid runners.

## Inputs

This method expects:

- a normalized benchmark bundle for the historical case,
- repeated-run summary artifacts for the key pooled results,
- and a normalized raw-evidence packet.

For the dormant puzzle reference case, those artifacts live under:

- `benchmarks/reference/dormant_puzzle_v1/`
- `benchmarks/reference/dormant_puzzle_v1/evidence/`

## What it generates

The unified submission runner synthesizes:

- a reference-case evidence report,
- a stats appendix,
- a raw-evidence appendix,
- a submission check,
- and a benchmark bundle.

That gives the historical case the same top-level packet shape as ordinary benchmark submissions.

## What it is good for

- historical reference cases,
- black-box investigations that should be archived rather than rerun,
- and benchmark packets built from trusted repeated-run summaries and control anchors.

## What it is not

- not a replacement for fresh baseline methods,
- not a permission to rerun third-party APIs at scale,
- and not a substitute for a local seeded benchmark track.

It is the bridge that lets historical cases live inside the benchmark ecosystem cleanly.
